# pedit — Claude-operated video editor: v0.1 design

Date: 2026-10-31 · Working name: **pedit** (final name TBD; must not contain "Claude")

## 1. Intent

A desktop video editor with a CapCut-style interface where **Claude does the editing**. The user arranges clips (or points at a folder) and tells Claude in a chat what they want; Claude edits the timeline through the editor's own tools while the user watches, reviews, corrects, and accepts. The user can still edit by hand at any time.

Target users: creators and editors making **Instagram Reels, YouTube videos and vlogs**. The founding use case is a travel vlog: ~1 hour of footage, imported in batches, cut down to ~5 minutes.

It runs entirely on the user's machine and uses the user's own Claude Code login via `claude -p` (no Agent SDK, no API keys, no cloud backend of ours).

### Why this, when OpenChatCut / SynthCut / VibeClip exist

Research (2026-10) found the existing open-source Claude/MCP editors are developer tools with these gaps. pedit wins on:

1. **Smooth 4K 120fps** — import never blocks, scrubbing never stutters (others: no proxies, or 4K unstated; 120fps unaddressed).
2. **CapCut-like UI** — download, open, edit; usable by non-developers.
3. **Safe Claude edits** — every Claude request produces a reviewable *draft*; nothing touches the real timeline until accepted.
4. **Anything that improves the editing experience or the final video** — later: visual understanding of non-speech footage (travel/b-roll), beat-synced cutting, history.

## 2. Goals, non-goals, anti-goals

**v0.1 goal:** prove the whole loop end to end — import → timeline → ask Claude → watch it work → review draft → accept/reject → export — with 4K 120fps footage playing smoothly.

**Demo that defines "done":** with a folder of 4K 120fps phone clips and a music file, the user types *"Put the Tokyo clips in order, trim each to 3 seconds, add a title 'Tokyo' at the start, put track_02 under it"*; Claude does it as a draft; the user previews, accepts, and exports a 9:16 MP4 at full quality.

**Long-term goal (not v0.1):** do essentially everything a Reels/YouTube/vlog editor does — cutting, captions, music sync, reframing, speed ramps, transitions, color, audio cleanup, titles/motion graphics, history.

**Non-goals for v0.1:** captions, transcripts, Python, shot logging/visual analysis, beat detection, versioning/history panel, effects/transitions/color, reframing, motion graphics, multiple video tracks, Mac/Windows packaging.

**Anti-goals (failure even if it "works"):**
- Import or scrubbing that lags or freezes on 4K 120fps.
- Claude changing the timeline in ways the user can't see, review, or undo.
- Claude acting on a stale view of the timeline and editing the wrong clip.
- Claude running arbitrary shell commands or touching files outside the editor's tools.
- Preview and export looking different.
- Requiring users to install Python, Node, Docker, or configure MCP by hand.
- Handling, storing, or proxying the user's Claude credentials.

## 3. Constraints

- **Claude access:** pedit is **for personal use**. The user runs their own logged-in, unmodified `claude` binary; the app never reads or stores credentials. (Anthropic's legal page permits end users signing in to the unmodified binary; revisit only if pedit is ever distributed.)
- **Usage limits:** users may be on the $20 Pro plan. Keep Claude's context lean: short tool results, no images in v0.1.
- **Footage:** must handle 4K 120fps, including 10-bit HEVC from phones/action cams (browsers decode HEVC unreliably → proxies required).
- **Platform:** developer is on Linux; Linux first, design must not block Mac/Windows.
- **Licensing: personal use only (decided by user) — no license constraints.** Bundle a **full GPL ffmpeg build** (libx264, libx265, zscale/libplacebo, NVENC/QSV/VAAPI). Code, libraries and assets may be taken freely from anywhere, including GPL/AGPL projects (OpenChatCut, SynthCut) and Remotion.

## 4. Decisions made in brainstorming

### 4.1 UI layout (decided by user)
CapCut-style dark UI, four columns plus timeline:

```
┌──────────────────────── top bar: project · undo/redo · format · Export ────────────────────────┐
│ Media        │ Preview                         │ Properties   │ Claude chat (full height)       │
│ (tabs:       │ play/pause/scrub, timecode      │ speed,       │ - user + Claude messages        │
│  Media,      │                                 │ volume,      │ - live step list per request    │
│  Audio,      │                                 │ transform,   │ - draft bar: Preview / Accept / │
│  Text)       │                                 │ text style   │   Reject                        │
├──────────────┴─────────────────────────────────┴──────────────┤ - input; clips can be dragged  │
│ Timeline (video · text · music tracks)                        │   in as tags                    │
└───────────────────────────────────────────────────────────────┴─────────────────────────────────┘
```
Mockup: `.superpowers/brainstorm/*/content/layout-v2.html`.

### 4.2 Safe edits (decided by user)
Every Claude request writes to a **draft** (a copy of the timeline). The timeline shows the draft overlaid: added clips striped purple, removed clips red-dashed, changed clips outlined. The draft bar offers **Preview draft / Accept / Reject**. Accept applies the draft as **one undo step**. The user can keep chatting to refine a pending draft.

### 4.3 Versioning (decided by user; v0.5, not v0.1)
Main use: going back after bad edits; secondary: alternate cuts (branches). Every accepted draft + periodic auto-saves become versions labelled with the request; restore never destroys (creates a new version). Implemented with isomorphic-git over the project folder (never media). v0.1 must keep the project as plain files so this drops in later.

### 4.4 Tech stack (proposed by Claude, accepted by user)
- **Shell:** Electron (consistent Chromium/WebCodecs on all OSes; Tauri's WebKitGTK on Linux lacks WebCodecs).
- **UI:** React + TypeScript + Vite, Zustand, Tailwind + Radix. Timeline rendered on `<canvas>`.
- **Preview:** WebCodecs (decode) + Mediabunny (demux) + WebGL2 (composite) + Web Audio, playing proxies.
- **Core (Electron main, TypeScript):** project store, command layer, draft manager, MCP server, Claude runner, media pipeline.
- **MCP:** `@modelcontextprotocol/sdk`, Streamable HTTP on 127.0.0.1, random per-launch token.
- **Media:** bundled static ffmpeg/ffprobe; hardware encoders when available.
- **Python (from v0.2):** uv-managed Python 3.12 + FastAPI analysis service, downloadable add-on packs (WhisperX, pyannote, beat_this, PySceneDetect, SigLIP, MediaPipe/YOLO, Demucs, DeepFilterNet). Claude still sees one MCP server (TypeScript), which calls Python. Not in v0.1.
- **Packaging:** electron-builder, Linux AppImage first.
- **Tests:** Vitest, Playwright (Electron), pytest later.

## 5. v0.1 design

### 5.1 Processes

```
Renderer (React UI) ⇄ IPC ⇄ Main process (Node/TS)
                              ├ ProjectStore + CommandLayer + DraftManager
                              ├ MediaPipeline (ffprobe, thumbnails, waveforms, proxies) – job queue
                              ├ MCP server (127.0.0.1:<port>, token)  ◄──┐
                              └ ClaudeRunner ── spawns `claude -p …` ────┘ (Claude calls MCP tools)
```
The renderer never runs ffmpeg or Claude; main never decodes frames for preview.

### 5.2 Project on disk

```
MyProject.pedit/
  project.json        # timeline + media refs + settings (small, diffable)
  chat.jsonl          # chat transcript + Claude session id
  cache/              # proxies, thumbnails, waveforms (regenerable, excluded from history later)
```
Media is **referenced by absolute path, never copied**. Missing media shows as offline with a "locate" action.

### 5.3 Timeline model (sketch)

```ts
Project   { id, revision, settings: { width, height, fps }, media: MediaItem[], tracks: Track[] }
MediaItem { id, path, folder /* relative to import root */, kind: 'video'|'audio'|'image', createdAt? /* capture time from container metadata, else file mtime */,
            importIndex, durationMs, width, height, fps, codec, bitDepth, colorTransfer /* sdr|hlg|pq */, hasAudio, proxyPath?, status }
Track     { id, kind: 'video'|'text'|'audio', items: Item[] }
VideoItem { id, mediaId, startMs, inMs, outMs, volume, speed? }   // speed UI-only in v0.1 optional
TextItem  { id, startMs, durationMs, text, style: { font, size, color, position } }
AudioItem { id, mediaId, startMs, inMs, outMs, volume }
```
- IDs are stable and opaque; nothing addresses items by position.
- `revision` increments on every committed change.
- v0.1: exactly one video, one text, one audio track. No overlaps within a track (video track is a ripple sequence; inserting/deleting closes gaps — builder may choose gap-allowing if simpler, but must be consistent for UI and Claude).
- Times stored in milliseconds; snapping to project frame boundaries at export.

### 5.4 Command layer
All mutations — UI and Claude — go through the same commands: `addClip, removeItem, moveItem, trimItem, splitItem, addText, updateText, setMusic, setItemVolume, setProjectFormat`. Each command validates, applies to a given timeline (real or draft), and returns a short human-readable summary. UI undo/redo is a stack of committed commands; an accepted draft is one entry.

### 5.5 Draft flow
1. User sends a message → DraftManager creates a draft from the current timeline at revision R.
2. Claude's MCP edit tools apply commands to the draft only; UI shows the overlay live.
3. When Claude finishes, the draft bar appears. **Preview draft** plays the draft timeline.
4. **While a draft exists, the timeline shows and edits the draft** (decided by user). Hand edits by the user go into the draft through the same command layer, alongside Claude's. The real timeline cannot change until Accept or Reject, so it always stays at revision R — **no merge/re-apply logic is needed.** The draft has its own step-by-step undo/redo (covering both Claude's and the user's steps).
5. **Accept:** replace the real timeline with the draft atomically, revision++, one entry on the main undo stack. **Reject:** discard the draft; the timeline returns to R. Claude is told on its next turn what happened ("draft accepted" / "draft rejected" / "user edited the draft: …" as a short summary of the user's commands).
6. Refining: a new message while a draft is pending continues editing the same draft. Because the user may have edited the draft between turns, Claude must `get_timeline` first (enforced by `expectedRevision`).
7. One Claude request at a time per project; the input is disabled (with a Stop button) while it runs. Stop kills the process; partial draft remains reviewable.

### 5.6 MCP tools (v0.1)
Read: `get_timeline` (compact text summary + revision), `list_media` (id, filename, folder, capture time, duration, resolution, fps, has audio; sorted by capture time — "in order" means capture order unless the user says otherwise), `get_project_settings`.
Edit (draft only): `add_clip(mediaId, inMs?, outMs?, atMs?|after?)`, `remove_item(id)`, `move_item(id, toMs|after)`, `trim_item(id, inMs?, outMs?)`, `split_item(id, atMs)`, `add_text(text, startMs, durationMs, style?)`, `update_text(id, …)`, `set_music(mediaId, inMs?, volume?)`, `set_volume(id, volume)`, `set_format('16:9'|'9:16'|'1:1')`.
- Every edit tool takes `expectedRevision` (draft revision); mismatch → error telling Claude to re-read.
- Results are one-line summaries (e.g. `trimmed clip c_8f2 to 0:03.0 (was 0:11.4)`), never full JSON dumps.
- No export tool in v0.1 (user exports). No file system or shell access.

### 5.7 Claude runner
Spawn per message:
```
claude -p "<message>" [--resume <sessionId>] \
  --mcp-config <generated json with url+token> --strict-mcp-config \
  --allowedTools "mcp__pedit__*" \
  --append-system-prompt "<contents of editor-guide.md>" \
  --output-format stream-json --verbose
```
- Parse stream-json events; show assistant text and each tool call as a step ("✓ trimmed shrine.mov to 3s").
- Store session id per project for `--resume`.
- Startup check: `claude` on PATH and logged in; if not, show setup instructions (install, run `claude` once to log in). Never read or store credentials.
- Handle: process exit codes, usage-limit errors (show clearly), timeouts, Stop button.
- `editor-guide.md` (shipped with app): what the editor is, timeline concepts, always `get_timeline` before editing, work in the draft, keep messages short, reels vs YouTube pacing basics.

### 5.8 Media pipeline
On import (files or folder):
1. **Immediately:** ffprobe (~50ms/file) → media item appears with metadata and placeholder.
2. **Background queue (bounded concurrency, never blocks UI):** poster thumbnail → filmstrip sprite → audio waveform peaks → **proxy**.
3. **Proxy spec:** H.264 MP4, ≤960px on the long edge (540p for 16:9), source fps capped at 60 (120 → 60 by frame dropping), keyframe every ~0.5s (short GOP for snappy seek), AAC audio. Encoder: detect `h264_nvenc` / `h264_qsv` / `h264_vaapi` / `h264_videotoolbox`; fall back to `libx264 -preset veryfast`.
4. Progress shown per clip in the Media panel; clips are usable on the timeline before the proxy finishes (preview shows "preparing" for those regions).
5. Cache keyed by file path + size + mtime.

### 5.9 Preview engine
- Plays the current timeline (or draft) from proxies.
- Demux with Mediabunny, decode with WebCodecs `VideoDecoder` (hardware), composite video + text in WebGL2 to a canvas sized to the project aspect; Web Audio mixes clip audio + music, audio clock drives playback.
- Seeking decodes from nearest keyframe; keep a small decoded-frame cache around the playhead and pre-roll the next clip before cut points so cuts are seamless.
- Text is rendered by one shared text renderer (canvas 2D → texture) — the **same renderer produces the PNGs used at export**.
- Target: 60fps playback, scrub response <100ms with a 10-minute timeline of 4K 120fps sources.
- **Reference machine** (the developer's laptop): Intel Raptor Lake iGPU + NVIDIA RTX 4050 Laptop, 16 threads, 22 GB RAM, Linux. Proxy budget there: 1 hour of 4K 120fps HEVC proxied in ≤30 min using NVDEC/NVENC (fallback VAAPI/QSV on the Intel iGPU). Proxies are built in timeline order first (clips already on the timeline, then by capture time). Also test on a CPU-only machine for the fallback path (slower is acceptable, never blocking).

### 5.10 Export
- User picks aspect (16:9 / 9:16 / 1:1), resolution (1080p or 4K/2160p on the long edge), fps (30 / 60 / source fps up to 120, never above the slowest-common source), and quality (bitrate preset). Default: 1080p, project fps. The demo passes at 1080p; 4K and 120fps must also work. The shared text renderer renders at the export resolution.
- **Color:** v0.1 exports **SDR Rec.709**. HDR sources (HLG/PQ, 10-bit) are tone-mapped to SDR with the **same ffmpeg filter chain** (zscale + tonemap, or libplacebo) in both proxy generation and export, so preview matches export. HDR export is a later feature. The bundled ffmpeg build must include zscale (or libplacebo).
- Main process builds an ffmpeg `filter_complex` from the timeline using **original files**: trim + scale/crop to fit format (center crop for aspect change in v0.1) + concat; text items rendered to transparent PNGs by the shared text renderer and overlaid with `enable=between(t,…)`; clip audio + music mixed with volumes.
- Encoder: hardware H.264/HEVC if available, else libx264/libx265. Progress bar + cancel.

### 5.11 UI behaviour (v0.1)
- Media panel: import button + drag-drop files/folders; grid with thumbnails, duration, proxy progress.
- Timeline: canvas, zoom, scroll, playhead, snapping; drag from media; drag to move; edge-drag to trim; split at playhead (S); delete; text track items editable in Properties; music track.
- Properties: for the selected item — volume, in/out, text content/style.
- Chat: messages, live step list, draft bar, clip tags by drag from Media (inserted as `@clipname` with mediaId attached), Stop button.
- Keyboard: space, J/K/L, S split, Delete, Ctrl+Z/Ctrl+Shift+Z, Ctrl+S.
- Autosave project.json on every committed change.

## 6. Roadmap after v0.1
- **0.2** Python service + uv + add-on packs; WhisperX captions (word-level), caption styles, filler/silence removal.
- **0.3** Shot logging: PySceneDetect, blur/shake/exposure scores, SigLIP embeddings + text search, aesthetic score, one-line shot notes written once by Claude from contact sheets and saved in the project.
- **0.4** Beat sync: beat_this downbeats/sections, cut-to-beat tools.
- **0.5** History panel and branches (isomorphic-git).
- **Later** transitions, speed ramps, color/LUTs, reframing with tracking, audio cleanup, multiple video tracks/PiP, Claude-written motion graphics (sandboxed, frame-deterministic, own renderer or Remotion), thumbnails, Mac/Windows builds.

## 7. Risks
1. **Preview engine** (WebCodecs + WebGL) is the hardest piece; build and benchmark it first with real 4K 120fps HEVC files.
2. **Anthropic subscription terms** may change; keep Claude integration behind one runner module.
3. **Usage limits** on Pro: measure tokens per typical request in v0.1.
4. **Hardware encode/decode variance** across GPUs/OSes; always have CPU fallback.
